# 从 Capacitor 8 升级到 Capacitor 9

本指南介绍如何将项目升级到当前的 Capacitor 9 版本，并列出官方插件中的破坏性变更。

:::note
本指南介绍应用层面的变更。如果你维护 Capacitor 插件，请改为参阅[将插件升级到 9.0](/main/updating/plugins/9-0.md)。
:::

## Cordova 支持现已变为可选

只有当项目实际安装了 Cordova 插件时，Capacitor 的 Cordova 兼容层才会包含在应用中。此前，无论应用是否使用 Cordova 插件，原生 Cordova 运行时（Android 上的 `capacitor-cordova-android` Gradle 模块和 plugins 模块，以及 iOS 上的 `CapacitorCordova` CocoaPods pod / SPM product）都会始终打包进每个应用。

现在运行 `npx cap sync`（或 `update`）时，会检测已安装的插件中是否有 Cordova 插件，只有检测到时才会接入 Cordova 运行时。如果项目没有 Cordova 插件，你会发现：

- 在 Android 上，生成的 `settings.gradle` 和应用的 `build.gradle` 不再包含 `capacitor-cordova-android` / `capacitor-cordova-android-plugins` 模块。
- 在 iOS 上，不再向 `Podfile` 或 `Package.swift` 添加 `CapacitorCordova`。

目前没有配置选项可以在不存在 Cordova 插件时强制包含 Cordova 运行时。如果应用的原生代码（或你维护的插件）直接引用 Capacitor Cordova 兼容层中的符号——例如 Android 上的 `com.getcapacitor.cordova.CordovaPlugin`，或 iOS 上 `CapacitorCordova` pod/product 中的任何内容——但项目并未安装真正的 Cordova 插件，那么升级后这些引用将无法解析。如果需要保留该兼容层，请添加一个 Cordova 插件依赖（哪怕是功能很简单的插件）；否则请删除直接引用。

## @capacitor/cli 中的破坏性变更

`cap run` 中分开的实时重载参数（`--live-reload`/`-l`、`--host`、`--port`、`--https`）现已合并为单个 `--url` 参数。过去需要这样运行：

```sh
npx cap run android -l --host 192.168.1.181 --port 5173
```

现在直接传入开发服务器（Vite、webpack 等）输出的完整 URL：

```sh
npx cap run android --url http://192.168.1.181:5173
```

## Node.js 24+

Capacitor 9 要求 Node.js 24 或更高版本。（建议使用最新的 LTS 版本。）与 Node 22 默认附带 npm 10 不同，Node 24 默认附带 npm 11。

## 使用 CLI 迁移

Capacitor 9 尚未正式发布，因此请在项目中安装 `next` 版本的 Capacitor CLI（9.0.0 正式发布后，请改用 `@latest`）：

```sh
npm i -D @capacitor/cli@next
```

安装后，只需运行以下命令，即可由 CLI 为你处理迁移。

```sh
npx cap migrate
```

如果迁移中的某些步骤无法自动完成，终端输出会提供更多信息。下文列出了手动迁移步骤。

无论选择哪种方式，最后都要完成 [iOS 迁移验证清单](#verify-the-ios-migration)。`npx cap migrate` 会改写与手动步骤相同的入口文件，因此迁移后的项目也需要进行相同检查。

## @capacitor/android 中的破坏性变更

`androidx.core:core` 1.19.0 将 `core-ktx` 合并进自身；AGP 9 原生捆绑 Kotlin Gradle Plugin，而 Gradle 9 则彻底移除了 `jcenter()`。这些变更通常不会直接影响应用，除非你（或旧版/社区插件）仍固定使用旧版 `core-ktx`、单独应用 Kotlin，或引用 `jcenter()`——请参阅下文的[将 core-ktx 迁移到 core](#migrate-core-ktx-to-core)和[更新 Kotlin 并移除 jcenter()](#update-kotlin-and-remove-jcenter)。

Capacitor 9 还移除了此前主要由插件作者使用、且在早期大版本中已弃用的 Java API——请参阅[代码中的破坏性变更](/main/updating/plugins/9-0.md#android)。如果应用包含自定义原生代码，也请检查该列表。

发布构建现在默认运行 R8，这可能导致 R8 无法识别为正在使用的代码被移除。请参阅下文的[在发布构建中启用 R8](#turn-on-r8-in-release-builds)。

## @capacitor/ios 中的破坏性变更

Capacitor 9 使用 SwiftUI `App` 结构体启动 iOS 应用，而不再使用 UIKit `AppDelegate`。项目会新增 `App.swift` 和 `CapacitorView.swift`，`AppDelegate` 会降为 `@UIApplicationDelegateAdaptor`，`SceneDelegate` 会清空，`Main.storyboard` 则会删除。所有应用都必须进行此变更，包括已升级到 8.5 的应用——请参阅下文的[采用 SwiftUI 入口点](#adopt-the-swiftui-entry-point)。

如果你从 Capacitor 8.4 或更早版本升级，也请阅读[升级到 8.5](/main/updating/8-5.md)。该指南介绍了 SwiftUI 入口点所依赖的 iOS UIScene 生命周期；其中的审查部分还列出了这两项变更都会影响的自定义原生代码模式。

Capacitor 9 还移除了此前主要由插件作者使用、且在早期大版本中已弃用的 Swift 和 Objective-C API——请参阅[代码中的破坏性变更](/main/updating/plugins/9-0.md#ios)。如果应用包含自定义原生代码（例如 AppDelegate 中的 `CAPBridge.handleOpenUrl`），也请检查该列表。

## iOS

以下指南介绍如何将 Capacitor 8 iOS 项目升级到 Capacitor 9。

### 升级 Xcode

Capacitor 9 要求使用 Xcode 27 或更高版本。

### 提高 iOS 部署目标版本

Capacitor 9 要求 iOS 16.0 或更高版本。

在 Xcode 项目中执行以下操作：在项目编辑器中选择 **Project**，然后打开 **Build Settings** 标签页。在 **Deployment** 部分，将 **iOS Deployment Target** 更改为 **iOS 16.0**。对所有应用 **Targets** 重复相同操作。

然后，如果项目使用 CocoaPods，请打开 `ios/App/Podfile` 并将 iOS 版本更新为 16.0：

```ruby
platform :ios, '16.0'
```

### 采用 SwiftUI 入口点 {#adopt-the-swiftui-entry-point}

`@main` 将从 `AppDelegate.swift` 移到新的 `App.swift`；SwiftUI 会声明应用的场景，并通过 `UIViewControllerRepresentable` 在该场景中承载 `CAPBridgeViewController`。被替换的 UIKit 入口点——`Main.storyboard`、由 AppDelegate 持有的 `UIWindow`，以及 `SceneDelegate` 中的窗口设置——都将移除。

:::warning
Swift 6（随 Xcode 27 一同提供）会拒绝已弃用的 `@UIApplicationMain` 属性，但不要将它替换为 `@main`。在 Capacitor 9 中，`@main` 应放在 `App.swift` 的 `App` 结构体上。请从 `AppDelegate` 中删除该属性——应用声明两个入口点将无法编译。
:::

以下文件会发生变化：

- `App.swift` — 新增。一个遵循 `App` 协议的 `@main` 结构体。它通过 `@UIApplicationDelegateAdaptor` 接入 `AppDelegate`，并声明一个包含 `CapacitorView()` 的 `WindowGroup` 场景。
- `CapacitorView.swift` — 新增。一个 `UIViewControllerRepresentable`，让 SwiftUI 可以承载 `CAPBridgeViewController`。
- `SceneDelegate.swift` — 清空。保留类声明，不包含任何方法。
- `AppDelegate.swift` — 降为辅助角色。它遵循 `NSObject` 而不是 `UIResponder`，并保留 `application(_:didFinishLaunchingWithOptions:)` 和 `application(_:configurationForConnecting:options:)`。移除 `@main` 属性、`window` 属性、`application(_:open:options:)` 和 `application(_:continue:restorationHandler:)`。
- `Info.plist` — `UIApplicationSceneManifest` 将简化为 `UIApplicationSupportsMultipleScenes`，因为现在由 AppDelegate 在代码中构建场景配置。移除 `UIMainStoryboardFile`。
- `Base.lproj/Main.storyboard` — 删除。保留 `LaunchScreen.storyboard`；iOS 仍要求提供启动 storyboard。

SPM 和 CocoaPods 模板中的 `App.swift`、`CapacitorView.swift`、`SceneDelegate.swift` 和 `AppDelegate.swift` 是相同文件，因此下文步骤适用于两者。

### CLI 会自动迁移的内容

对于仍符合 Capacitor 模板结构的项目，`npx cap migrate` 会应用完整变更：写入 `App.swift`、`CapacitorView.swift` 和 `SceneDelegate.swift`，将这三个文件注册到 Xcode App target，改写 `AppDelegate.swift`、更新 `Info.plist`，并删除 `Main.storyboard`。每个步骤都具有幂等性，因此如果迁移中途停止，再次运行 `npx cap migrate` 即可完成。若项目在 SceneDelegate 模板加入前就已迁移，也同样适用：再次运行 `npx cap migrate`，它会添加缺失文件及相应配置。

如果 `AppDelegate.swift` 存在以下情况，迁移器会跳过自动改写并输出手动操作步骤：

- 不包含 `AppDelegate` 类；
- 自行管理 `UIWindow`，而现在窗口由 SwiftUI `App` 结构体持有；
- 包含自定义的 `application(_:open:options:)` 或 `application(_:continue:restorationHandler:)` 方法体，因为场景不再调用这些方法。

请留意终端输出中的以下三种部分迁移情况：

- 如果 `AppDelegate.swift` 中包含你编写的代码，迁移器会就地转换，而不是用 Capacitor 9 模板替换。请对照下文第 4 步检查文件中保留的内容。
- 如果 `SceneDelegate.swift` 中包含你编写的代码，迁移器会保留而不是清空该文件，它仍然是应用的场景代理。请按第 3 步所述，将窗口设置移到 `App.swift`，并将 URL 和活动处理移到 SwiftUI 场景主体中。
- 如果 `UIApplicationSceneManifest` 指定的场景代理类不是 `SceneDelegate`，迁移器会保持不变。完成该代理迁移后，按第 5 步操作。

### 手动迁移入口点

当 `npx cap migrate` 跳过改写，或你希望自行应用变更时，请按以下步骤操作。以下步骤以 Capacitor 8.5 项目为起点；如果你使用的是 8.4 或更早版本，请先[采用 UIScene 生命周期](/main/updating/8-5.md)。

#### 1. 添加 App.swift

创建 `App/App/App.swift`。这是应用的新入口点：

```swift
import SwiftUI
import Capacitor

@main
struct CapacitorApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) var appDelegate

    var body: some Scene {
        WindowGroup {
            CapacitorView()
                .ignoresSafeArea()
                .onOpenURL { url in
                    SceneDelegateProxy.shared.handle(openURL: url)
                }
                .onContinueUserActivity(NSUserActivityTypeBrowsingWeb) { activity in
                    SceneDelegateProxy.shared.handle(userActivity: activity)
                }
        }
    }
}
```

`@UIApplicationDelegateAdaptor` 会使 `AppDelegate` 保持存活，以处理在场景生命周期中仍有效的应用级回调，例如推送通知注册。`.ignoresSafeArea()` 会将整个窗口交给 WebView，由 WebView 管理自身的边距。

#### 2. 添加 CapacitorView.swift

创建 `App/App/CapacitorView.swift`。它封装桥接视图控制器，以便 SwiftUI 承载：

```swift
import SwiftUI
import Capacitor

public struct CapacitorView: UIViewControllerRepresentable {
    public func makeUIViewController(context: Context) -> CAPBridgeViewController {
        CAPBridgeViewController()
    }

    public func updateUIViewController(_ vc: CAPBridgeViewController, context: Context) {}
}
```

如果应用使用 `CAPBridgeViewController` 子类，请改为从 `makeUIViewController(context:)` 返回该子类。

#### 3. 清空 SceneDelegate.swift

现在窗口由 `App.swift` 持有，因此场景代理只保留类声明。将 `App/App/SceneDelegate.swift` 的主体替换为：

```swift
import UIKit

class SceneDelegate: UIResponder, UIWindowSceneDelegate {}
```

如果项目使用 Capacitor 8.4 或更早版本且没有 `SceneDelegate.swift`，请按上述内容创建该文件。即使类为空，它也必须存在：`application(_:configurationForConnecting:options:)` 会将其指定为 `delegateClass`，UIKit 会为每个场景实例化该类型。

旧 `SceneDelegate` 中的功能现在都有了新的归属。窗口创建移到 `App.swift`——`WindowGroup` 会构建窗口，`CapacitorView` 则提供根视图控制器。URL 和 universal link 处理移到 `App.swift` 中的 `.onOpenURL` 和 `.onContinueUserActivity` 修饰符；不要在此处重新实现 `scene(_:openURLContexts:)` 或 `scene(_:continue:)`，因为实现这些方法的场景代理会截走事件，使这些修饰符收不到通知。SwiftUI 未提供的逐场景 UIKit API（例如 `preferredWindowingControlStyle(for:)`）才是保留该类的用途——需要时可在这里添加。

#### 4. 调整 AppDelegate.swift

现在入口点和窗口由 `App.swift` 持有，因此应移除 `@main` 属性和 `window` 属性。保留 `application(_:configurationForConnecting:options:)`：它负责将 `SceneDelegate` 指定为场景代理类，而 Info.plist 不再负责此事。

```diff
 import UIKit
-import Capacitor

-@main
-class AppDelegate: UIResponder, UIApplicationDelegate {
-
-    var window: UIWindow?
-
+class AppDelegate: NSObject, UIApplicationDelegate {
     func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
         return true
     }

-    func application(_ application: UIApplication,
-                     configurationForConnecting connectingSceneSession: UISceneSession,
-                     options: UIScene.ConnectionOptions) -> UISceneConfiguration {
-        let config = UISceneConfiguration(name: "Default Configuration",
-                                          sessionRole: connectingSceneSession.role)
-        config.delegateClass = SceneDelegate.self
-        return config
-    }
+    func application(
+        _ application: UIApplication,
+        configurationForConnecting connectingSceneSession: UISceneSession,
+        options: UIScene.ConnectionOptions
+    ) -> UISceneConfiguration {
+        let configuration = UISceneConfiguration(name: nil, sessionRole: connectingSceneSession.role)
+        configuration.delegateClass = SceneDelegate.self
+        return configuration
+    }
 }
```

现在名称为 `nil`，因为第 5 步会删除 `UISceneConfigurations` 条目，而 `"Default Configuration"` 正是指向该条目的名称。这是此方法唯一的行为变更；其余改写只是采用 Capacitor 9 模板的格式，因此最终文件将与通过 `npx cap migrate` 迁移或全新创建的项目一致。如果项目使用 Capacitor 8.4 或更早版本且没有 `configurationForConnecting` 方法，请添加上述方法——否则 UIKit 创建场景时不会设置你的代理，也就没有对象可以响应逐场景回调。

如果 `AppDelegate` 仍声明 `application(_:open:options:)` 或 `application(_:continue:restorationHandler:)`，这两个方法都已不再生效：采用 8.5 中的 UIScene 生命周期后，场景就不再调用它们。根据各自的方法体决定如何处理：

- 如果方法体仅返回 `ApplicationDelegateProxy.shared.application(...)`——这是 8.5 之前模板提供的实现——请删除该方法。现在 SwiftUI 场景主体会将事件转发给代理。
- 如果你添加了自定义处理，请先将其移到 `App.swift` 中的 `.onOpenURL` 或 `.onContinueUserActivity` 闭包，再删除该方法。请参阅[路由处理 URL scheme 和 universal link](#route-url-schemes-and-universal-links)。

8.5 之前的模板会在每个方法上方的注释中提示你添加自定义代码，因此删除前请先阅读方法体。出于同样的原因，`npx cap migrate` 发现任一方法包含自定义方法体时，会跳过自动改写。

旧版模板提供的空方法 `applicationWillResignActive`、`applicationDidEnterBackground`、`applicationWillEnterForeground`、`applicationDidBecomeActive` 和 `applicationWillTerminate` 在场景生命周期下也不会被调用。Capacitor 9 模板会删除这些方法。如果你向其中任何方法添加了代码，请在删除方法前迁移这些代码。

#### 5. 更新 Info.plist

`application(_:configurationForConnecting:options:)` 会在代码中构建场景配置，因此清单不再需要指定配置、代理类或 storyboard。将其简化为单个键；如果项目仍设置了 `UIMainStoryboardFile`，也请将其删除：

```diff
 <key>UIApplicationSceneManifest</key>
 <dict>
     <key>UIApplicationSupportsMultipleScenes</key>
     <false/>
-    <key>UISceneConfigurations</key>
-    <dict>
-        <key>UIWindowSceneSessionRoleApplication</key>
-        <array>
-            <dict>
-                <key>UISceneConfigurationName</key>
-                <string>Default Configuration</string>
-                <key>UISceneDelegateClassName</key>
-                <string>$(PRODUCT_MODULE_NAME).SceneDelegate</string>
-                <key>UISceneStoryboardFile</key>
-                <string>Main</string>
-            </dict>
-        </array>
-    </dict>
 </dict>
 <key>UILaunchStoryboardName</key>
 <string>LaunchScreen</string>
```

保留 `UILaunchStoryboardName` 不变。仍然需要 `LaunchScreen.storyboard`。

#### 6. 删除 Main.storyboard

现在由 `CapacitorView` 提供根视图控制器，因此主 storyboard 已无用途。删除 `App/App/Base.lproj/Main.storyboard`，并从 App target 中移除其引用。通过 Xcode 删除文件会自动移除引用；如果手动编辑 `project.pbxproj`，则需要移除对应的 `PBXFileReference`、`PBXBuildFile`、group 条目和 build phase 条目。

保留 `LaunchScreen.storyboard` 不变。

#### 7. 注册新文件并同步

将 `App.swift`、`CapacitorView.swift` 和 `SceneDelegate.swift` 添加到 App target。通过 IDE 添加文件时，Xcode 会自动完成此操作。手动添加时，每个文件都需要一个 `PBXFileReference`、一个 `PBXBuildFile`、一个 `App` group 条目，以及 target 的 Sources build phase 中的一个条目。

然后运行 `npx cap sync ios`。

### 路由处理 URL scheme 和 universal link {#route-url-schemes-and-universal-links}

自定义 URL scheme 和 universal link 会通过 SwiftUI 场景主体到达应用。`.onOpenURL` 会转发到 `SceneDelegateProxy.shared.handle(openURL:)`，`.onContinueUserActivity(NSUserActivityTypeBrowsingWeb)` 会转发到 `SceneDelegateProxy.shared.handle(userActivity:)`；它们会发布与此前 AppDelegate 和场景代理路径相同的通知。监听 `.capacitorOpenURL` 或 `.capacitorOpenUniversalLink` 的插件仍可正常工作，`App.getLaunchUrl()` 也仍会返回启动 URL。

应用自己的路由处理也应放在同一位置。过去位于 `AppDelegate.application(_:open:options:)` 或 `SceneDelegate.scene(_:openURLContexts:)` 中的代码，应放入 `.onOpenURL` 闭包，并与转发调用并列：

```diff
     var body: some Scene {
         WindowGroup {
             CapacitorView()
                 .ignoresSafeArea()
                 .onOpenURL { url in
+                    MyRouter.handle(url)
                     SceneDelegateProxy.shared.handle(openURL: url)
                 }
                 .onContinueUserActivity(NSUserActivityTypeBrowsingWeb) { activity in
                     SceneDelegateProxy.shared.handle(userActivity: activity)
                 }
         }
     }
```

:::warning
不要将这些路由处理放到 `SceneDelegate` 中。实现 `scene(_:openURLContexts:)` 或 `scene(_:continue:)` 的场景代理会截走事件，使 SwiftUI 修饰符收不到通知：`.onOpenURL` 和 `.onContinueUserActivity` 将停止触发，链接也无法到达桥接层。出于这个原因，Capacitor 9 的 `SceneDelegate` 为空。
:::

### 审查自定义原生代码 {#audit-your-custom-native-code}

大多数应用只需完成上述步骤。请检查自己的原生代码和自定义插件中是否存在以下模式；`npx cap migrate` 发现这些模式时也会报告：

- 在 `App.swift` 以外创建或配置 `UIWindow`。现在窗口由 SwiftUI `App` 结构体持有。根视图控制器的自定义配置应放在 `CapacitorView` 中，窗口级配置则应放在场景主体中。
- 自定义的 `application(_:open:options:)` 或 `application(_:continue:restorationHandler:)` 方法体。请按上文所示将它们移到 SwiftUI 场景主体中。
- 在 `SceneDelegate` 中实现 `scene(_:willConnectTo:options:)`、`scene(_:openURLContexts:)` 或 `scene(_:continue:)`。窗口设置应移到 `App.swift`，链接处理则应移到场景主体——保留 URL 或活动处理方法会导致 SwiftUI 修饰符失效。其他逐场景 UIKit 方法可以保留。
- `UIApplication.shared.applicationState`。请改为读取窗口场景的 `activationState`。
- `tmpWindow` 或 `TmpViewController`。这两者已在 Capacitor 8.5 中移除。请使用桥接层的 `viewController` 作为呈现锚点。

[8.5 指南中的审查部分](/main/updating/8-5.md#audit-your-custom-code-and-plugins)对这些模式中与 UIScene 相关的部分有更详细说明。

### 验证 iOS 迁移 {#verify-the-ios-migration}

迁移后，请在设备或模拟器上完成以下检查；无论是通过 `npx cap migrate` 应用变更，还是按手动步骤操作，都需要检查。

所有应用都应检查：

- 项目可在 Xcode 27 中成功构建，且没有重复入口点错误。
- 应用可启动并呈现 Web 应用。
- 应用进入后台和返回前台时会触发 JavaScript `pause` 和 `resume` 事件。

如果应用注册了自定义 URL scheme：

- 无论冷启动（应用已关闭后点击链接）还是热启动（应用已在运行），链接都能打开应用。请在这两种情况下检查 `appUrlOpen` 监听器和 `App.getLaunchUrl()`。

如果应用处理 universal link：

- 关联域名链接无论冷启动还是热启动，都能打开应用并路由到正确页面。请检查相同的两个接口：`appUrlOpen` 和 `App.getLaunchUrl()`。重点检查冷启动：链接会通过 `.onContinueUserActivity` 而不是 `.onOpenURL` 到达；如果 `SceneDelegate` 仍实现 `scene(_:continue:)`，就会在不报错的情况下截走事件。

如果应用包含自定义原生代码：

- [审查自定义原生代码](#audit-your-custom-native-code)中列出的模式均已清除，并且旧 `SceneDelegate` 或 `AppDelegate` 执行的功能仍然正常。

:::note
预计 CocoaPods Trunk 将于 2026 年 12 月 2 日变为只读。如果你还没有迁移，可以考虑[将应用迁移到 SPM](/main/ios/spm.md#using-spm-in-an-existing-capacitor-project)；新建 Capacitor 项目默认使用 SPM。
:::

## Android

以下指南介绍如何将 Capacitor 8 Android 项目升级到 Capacitor 9。

### 升级 Android Studio

Capacitor 9 要求使用 Android Studio 2026.1.4 或更高版本。

更新后，Android Studio 可以帮助完成部分 Gradle 相关更新。首先运行 `Tools -> AGP Upgrade Assistant`，并在下拉菜单中选择要升级到的版本 `9.4.1`。然后点击 `Run selected steps`。

![AGP 升级助手](../../../static/img/v6/docs/android/agp-upgrade-assistant.png)

### 清理 gradle.properties

AGP 9 更改了多个 `gradle.properties` 标志的默认值，AGP Upgrade Assistant 会显式写回这些标志，以保持 AGP 8 的行为。Capacitor 应用不需要其中任何一项：大多数标志已弃用，并将在 AGP 10 中移除；其中几项还会直接破坏 Capacitor 9 构建（`android.builtInKotlin=false` 会关闭 AGP 9 现在内置的 Kotlin 支持，而 `android.sdk.defaultTargetSdkToCompileSdkIfUnset=false` 会阻止 AGP 推断 `targetSdkVersion`）。请删除这些设置：

```diff
# gradle.properties

- android.defaults.buildfeatures.resvalues=true
- android.sdk.defaultTargetSdkToCompileSdkIfUnset=false
- android.enableAppCompileTimeRClass=false
- android.usesSdkInManifest.disallowed=false
- android.uniquePackageNames=false
- android.dependency.useConstraints=true
- android.r8.strictFullModeForKeepRules=false
- android.r8.optimizedResourceShrinking=false
- android.builtInKotlin=false
- android.newDsl=false
```

### 更新 Android 项目变量

在 `variables.gradle` 文件中，将变量值更新为以下最低版本：

```groovy
minSdkVersion = 26
compileSdkVersion = 37
targetSdkVersion = 37
androidxActivityVersion = '1.13.0'
androidxAppCompatVersion = '1.8.0'
androidxCoordinatorLayoutVersion = '1.3.0'
androidxCoreVersion = '1.19.1'
androidxFragmentVersion = '1.9.1'
coreSplashScreenVersion = '1.2.0'
androidxWebkitVersion = '1.17.1'
junitVersion = '4.13.2'
androidxJunitVersion = '1.3.0'
androidxEspressoCoreVersion = '3.7.0'
cordovaAndroidVersion = '15.1.0'
```

### 从应用的 build.gradle 中移除 targetSdkVersion

如果未显式设置 `targetSdkVersion`，AGP 9 会根据 `compileSdkVersion` 推断该值，因此可以将其移除：

```diff
defaultConfig {
    applicationId "com.getcapacitor.app"
    minSdkVersion rootProject.ext.minSdkVersion
-   targetSdkVersion rootProject.ext.targetSdkVersion
    versionCode 1
    versionName "1.0"
}
```

### 重命名默认 ProGuard 文件

AGP 9 已移除 `proguard-android.txt`。请在 `app/build.gradle` 中将其替换为 `proguard-android-optimize.txt`，该文件还会启用 ProGuard 优化：

```diff
buildTypes {
    release {
        minifyEnabled false
-       proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
+       proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
}
```

### 在发布构建中启用 R8 {#turn-on-r8-in-release-builds}

新的 Capacitor 9 应用使用 R8 构建发布版本；R8 会缩减、优化并混淆应用代码，`npx cap migrate` 也会在现有应用中启用它。从 2027 年 2 月起，Google Play 将对较大型应用[要求进行代码优化](https://support.google.com/googleplay/android-developer/answer/17492799)。如果 `npx cap migrate` 警告无法设置 `minifyEnabled`，请在 `app/build.gradle` 的 release 块中设置：

```diff
buildTypes {
    release {
-       minifyEnabled false
+       minifyEnabled true
        proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
}
```

R8 只在发布构建中运行，因此更新后请测试应用的发布构建。如果问题只在发布版本中出现，请参阅[使用 R8](/main/android/troubleshooting.md#using-r8)。如需关闭 R8，请设置 `minifyEnabled false`。

### 在应用的 build.gradle 中声明依赖版本

你的 `app/build.gradle` 引用了在根项目 `variables.gradle` 中声明的版本变量，并依赖 Gradle 沿项目层级向上查找这些变量。Gradle 9.6 已弃用这种隐式查找方式，Gradle 10 中则会将其视为错误，因此请在文件顶部显式声明：

```diff
apply plugin: 'com.android.application'

+ def androidxAppCompatVersion = rootProject.ext.androidxAppCompatVersion
+ def androidxCoordinatorLayoutVersion = rootProject.ext.androidxCoordinatorLayoutVersion
+ def coreSplashScreenVersion = rootProject.ext.coreSplashScreenVersion
+ def junitVersion = rootProject.ext.junitVersion
+ def androidxJunitVersion = rootProject.ext.androidxJunitVersion
+ def androidxEspressoCoreVersion = rootProject.ext.androidxEspressoCoreVersion

android {
```

以上是 Capacitor 模板声明的变量。如果应用还引用了 `variables.gradle` 中的其他变量（例如本地插件使用的依赖版本），也请在此处声明。

### 将 core-ktx 迁移到 core {#migrate-core-ktx-to-core}

`androidx.core:core` 1.19.0 将 `core-ktx` 之前提供的所有扩展函数合并到 `core` 本身，使 `core-ktx` 成为一个空的兼容性 artifact。如果应用（或其依赖的旧版/社区插件）仍显式依赖低于 `1.19.0` 的 `core-ktx`，构建时可能会遇到重复类错误；请移除该依赖，或改为依赖 `core`：

```diff
dependencies {
-   implementation "androidx.core:core-ktx:1.17.0"
+   implementation "androidx.core:core:1.19.0"
}
```

### 更新 Kotlin 并移除 jcenter() {#update-kotlin-and-remove-jcenter}

AGP 9 原生捆绑 Kotlin Gradle Plugin（Kotlin `2.2.10`），不再要求将其作为独立插件应用。如果 `build.gradle` 仍直接应用 `kotlin-android`，或声明独立的 `kotlin-stdlib` / `kotlin-gradle-plugin` 依赖，请将其移除——与 AGP 9 内置的 Kotlin 并存会导致重复插件构建失败：

```diff
buildscript {
    dependencies {
        classpath 'com.android.tools.build:gradle:9.4.1'
-       classpath "org.jetbrains.kotlin:kotlin-gradle-plugin:2.2.20"
    }
}
-apply plugin: 'kotlin-android'

dependencies {
-   implementation "org.jetbrains.kotlin:kotlin-stdlib:2.2.20"
}
```

Gradle 9 也彻底移除了 `jcenter()` 仓库辅助方法（自 2024 年起，该仓库已重定向到 Maven Central）。任何仍调用它的 `build.gradle` 都会在 Gradle 配置阶段失败：

```diff
repositories {
    google()
-   jcenter()
+   mavenCentral()
}
```

### 更新 Google services 插件

```diff
# build.gradle

    dependencies {
        classpath 'com.android.tools.build:gradle:9.4.1'
-       classpath 'com.google.gms:google-services:4.4.4'
+       classpath 'com.google.gms:google-services:4.5.0'

```

### 将 Gradle 插件更新到 9.4.1

```diff
# build.gradle

    dependencies {
-       classpath 'com.android.tools.build:gradle:8.13.0'
+       classpath 'com.android.tools.build:gradle:9.4.1'

```

### 将 Gradle wrapper 更新到 9.8.2

```diff
# gradle-wrapper.properties

distributionBase=GRADLE_USER_HOME
distributionPath=wrapper/dists
- distributionUrl=https\://services.gradle.org/distributions/gradle-8.14.3-all.zip
+ distributionUrl=https\://services.gradle.org/distributions/gradle-9.8.2-all.zip
zipStoreBase=GRADLE_USER_HOME
zipStorePath=wrapper/dists
```

## 插件

插件已更新到 9.0.0，请确保将它们更新到最新版本。

以下插件功能已修改或移除。请相应更新代码。

### Action Sheet

- `androidxMaterialVersion` 变量已更新为 `1.14.0`。

### Barcode Scanner

- `kotlinxCoroutinesVersion` 变量已更新为 `1.11.0`。

### Browser

- `androidxBrowserVersion` 变量已更新为 `1.10.0`。

### Camera

- `androidxExifInterfaceVersion` 变量已更新为 `1.4.2`。
- `androidxMaterialVersion` 变量已更新为 `1.14.0`。

### Geolocation

- `playServicesLocationVersion` 变量已更新为 `21.4.0`。
- `kotlinxCoroutinesVersion` 变量已更新为 `1.11.0`。

### Google Maps

- `kotlinxCoroutinesVersion` 变量已更新为 `1.11.0`。
- `googleMapsPlayServicesVersion` 变量已更新为 `20.0.0`。
- `googleMapsUtilsVersion` 变量已更新为 `5.0.0`。
- `googleMapsKtxVersion` 和 `googleMapsUtilsKtxVersion` 变量已更新为 `6.0.1`。

### InAppBrowser

- `androidxBrowserVersion` 变量已更新为 `1.10.0`。

### Push Notifications

iOS 上不再支持已弃用的 `alert` 展示选项。请改用 `banner` 和/或 `list`。

### Splash Screen

Android 上 `launchFadeOutDuration` 的默认值已从 `200` 更改为 `0`，因为此前的默认值可能会阻止 `SplashScreen.hide()` 之后立即进行的 UI 更改。如果应用依赖此前 200 毫秒的淡出动画，请在 Capacitor 配置中显式设置 `launchFadeOutDuration: 200`。
