# 代码中的破坏性变更

## Android

`@NativePlugin` 注解以及该时期引入的若干已弃用权限和 Activity 结果 API 均已移除。有关整体迁移方式，请参阅 [Capacitor 3 插件迁移指南](/updating/plugins/3-0)。

| 已移除 | 替代方案 |
| :------ | :---------- |
| `@NativePlugin` 注解 | `@CapacitorPlugin` |
| `Plugin.saveCall(PluginCall)` | `Bridge.saveCall(PluginCall)` 或 `PluginCall.setKeepAlive(true)` |
| `Plugin.getSavedCall()`（无参） | `Bridge.getSavedCall(String)` |
| `Plugin.freeSavedCall()` | `PluginCall.release(Bridge)` |
| `Plugin.hasDefinedPermissions(String[])` | `Plugin.isPermissionDeclared(String)` |
| `Plugin.hasPermission(String)` | `Plugin.getPermissionState(String)` / `getPermissionStates()`，或 `ActivityCompat.checkSelfPermission(Context, String)` |
| `Plugin.pluginRequestPermission(String, int)` | `Plugin.requestPermissionForAlias(...)`，配合 `@PermissionCallback` 使用 |
| `Plugin.pluginRequestPermissions(String[], int)` | `Plugin.requestPermissionForAliases(...)`，配合 `@PermissionCallback` 使用 |
| `Plugin.pluginRequestAllPermissions()` | `Plugin.requestAllPermissions(PluginCall, String)`，配合 `@PermissionCallback` 使用 |
| `Plugin.startActivityForResult(PluginCall, Intent, int)` | `Plugin.startActivityForResult(PluginCall, Intent, String)`，配合 `@ActivityCallback` 使用 |
| `Bridge.startActivityForPluginWithResult(PluginCall, Intent, int)` | `Plugin.startActivityForResult(PluginCall, Intent, String)`，配合 `@ActivityCallback` 使用 |

Capacitor 9 还移除了先前主要版本中弃用的其余 Java API。如果你的插件仍在使用其中任何 API，请按下表替换：

| 已移除 | 替代方案 |
| :------ | :---------- |
| `CapConfig(AssetManager, JSONObject)` 构造函数 | 使用 `CapConfig.loadDefault(Context)` 从 `capacitor.config.json` 加载，或在嵌入式场景中使用 `CapConfig.Builder` |
| `CapConfig.getObject(String)`、`getString(...)`、`getBoolean(...)`、`getInt(...)`、`getArray(...)` | 对主配置值使用 `CapConfig` 的类型化 getter；对插件配置值使用 `PluginConfig` 访问器 |
| `PluginCall.save()` | `setKeepAlive(true)` |
| `PluginCall.isSaved()` | `isKeptAlive()` |
| `PluginCall.hasOption(String)` | 类型化访问器（`getString(...)`、`getInt(...)` 等） |
| `PluginCall.isReleased()` | 无替代方案，已释放的调用由 bridge 管理 |
| `Bridge.CAPACITOR_HTTPS_INTERCEPTOR_START` | `CAPACITOR_HTTP_INTERCEPTOR_START`，所有代理请求均由它处理 |
| `Plugin.getConfigValue(String)` | `getConfig()` 和 `PluginConfig` 上的类型化访问器 |
| `MessageHandler(Bridge, WebView, Object)` 构造函数 | `MessageHandler(Bridge, WebView)` |
| `WebViewLocalServer.PathHandler.getResponseHeaders()` | `buildDefaultResponseHeaders()` |

## iOS

Capacitor 9 移除了先前主要版本中弃用的 Swift 和 Objective-C API。如果你的插件仍在使用其中任何 API，请按下表替换。

### 已移除 `CAPBridge` 兼容类

`CAPBridge` 类是一个兼容性垫片，现已完全移除。请使用以下替代方案：

| 已移除 | 替代方案 |
| :------ | :---------- |
| `CAPBridge.statusBarTappedNotification` | `Notification.Name.capacitorStatusBarTapped` |
| `CAPBridge.getLastUrl()` | `ApplicationDelegateProxy.shared.lastURL` |
| `CAPBridge.handleOpenUrl(_:_:)` | `ApplicationDelegateProxy.shared.application(_:open:options:)` |
| `CAPBridge.handleContinueActivity(_:_:)` | `ApplicationDelegateProxy.shared.application(_:continue:restorationHandler:)` |
| `CAPBridge.handleAppBecameActive(_:)` | 不再需要，此方法原本不执行任何操作 |

### 已移除 Bridge（`CAPBridgeProtocol`）方法

| 已移除 | 替代方案 |
| :------ | :---------- |
| `getWebView()` | `webView` 属性 |
| `isSimulator()` | `isSimEnvironment` 属性 |
| `isDevMode()` | `isDevEnvironment` 属性 |
| `getStatusBarVisible()` / `setStatusBarVisible(_:)` | `statusBarVisible` 属性 |
| `getStatusBarStyle()` / `setStatusBarStyle(_:)` | `statusBarStyle` 属性 |
| `setStatusBarAnimation(_:)` | `statusBarAnimation` 属性 |
| `getUserInterfaceStyle()` | `userInterfaceStyle` 属性 |
| `getLocalUrl()` | `config.localURL` |
| `getSavedCall(_:)` | `savedCall(withID:)` |
| `releaseCall(callbackId:)` | `releaseCall(withID:)` |
| `presentVC(_:animated:completion:)` | `viewController?.present(_:animated:completion:)` |
| `dismissVC(animated:completion:)` | `viewController?.dismiss(animated:completion:)` |
| `modulePrint(_:_:)` | `CAPLog.print(_:)` |

### 其他移除项

| 已移除 | 替代方案 |
| :------ | :---------- |
| `CAPNotifications` 枚举 | `Notification.Name.capacitor*` 常量（例如 `Notification.Name.capacitorOpenURL`） |
| `PluginCallErrorData`、`PluginResultData` 和 `JSResultBody` 类型别名 | `PluginCallResultData` |
| `CAPPluginCall.hasOption(_:)` | 类型化访问器（`getString(_:)`、`getInt(_:)` 等） |
| `JSDate.toString(_:)` | 不再需要，序列化时会将日期映射为字符串 |
| `InstanceConfiguration.getPluginConfigValue(_:_:)` | `getPluginConfig(_:)` |
| `InstanceConfiguration.getValue(_:)` / `getString(_:)` | 直接访问 `InstanceConfiguration` 的属性 |
| `CAPPlugin.getConfigValue(_:)` | `getConfig()` 和 `PluginConfig` 上的类型化访问器 |
| `CAPFileManager.getPortablePath(host:uri:)` | bridge 上的 `portablePath(fromLocalURL:)` |
| 接受 `cordovaConfiguration` 的 `CapacitorBridge` 初始化方法 | 不带 `cordovaConfiguration` 参数的初始化方法 |
| `CapacitorBridge.httpsInterceptorStartIdentifier` | `httpInterceptorStartIdentifier`，所有代理请求均由它处理 |
| `CapacitorUrlRequest.setRequestHeaders([String: String])` | `setRequestHeaders([String: Any])`。注意：替代方法会设置请求头值，而不是追加请求头，因此重复的键会覆盖之前的值 |

# 在插件中将 Capacitor 更新到 9.0

:::note
本指南介绍面向插件作者的变更。如果你要更新的是应用，请参阅[更新到 9.0](/main/updating/9-0.md)。
:::

:::note
Capacitor 9 尚未正式发布。下文中的依赖版本指向 `next` dist-tag / 当前预发布版本；9.0.0 发布后，请改用常规的 `^9.0.0` 版本范围。
:::

## 使用 @capacitor/plugin-migration-v8-to-v9

在插件目录中运行 `npx @capacitor/plugin-migration-v8-to-v9@latest`，它会自动完成大部分文件变更。

## 手动更新文件

### 更新 Capacitor 依赖

将 devDependencies 中的 `@capacitor/cli`、`@capacitor/core`、`@capacitor/android` 和 `@capacitor/ios` 更新为 `next`。
将 peerDependencies 中的 `@capacitor/core` 更新为 `>=9.0.0-alpha.6`（请查看 npm 上的当前预发布版本，因为它会定期更新）。

### Cordova 支持现在是可选的

现在，只有在使用该插件的应用实际安装了 Cordova 插件时，Capacitor 的 Cordova 兼容层才会接入该应用；Android 和 iOS 均如此。如果你的插件原生代码直接引用了 Capacitor Cordova 兼容层中的符号（例如 Android 上的 `com.getcapacitor.cordova.CordovaPlugin`），请注意：对于未安装任何 Cordova 插件的使用方应用，该兼容层可能不存在。目前没有配置选项可以强制包含此兼容层。

如果你的插件兼容 SPM，也请从 `Package.swift` 中移除无条件声明的 `Cordova` 产品依赖——不能再保证每个使用方项目中都包含它：

```diff
    dependencies: [
        .product(name: "Capacitor", package: "capacitor-swift-pm"),
-       .product(name: "Cordova", package: "capacitor-swift-pm"),
    ]
```

### 清理 gradle.properties

AGP 9 更改了若干 `gradle.properties` 标志的默认值，而 AGP Upgrade Assistant 会将这些标志显式写回，以保持 AGP 8 的构建行为。Capacitor 插件不需要这些标志：其中大多数已弃用，并将在 AGP 10 中移除；另外有两个会直接导致 Capacitor 9 构建失败（`android.builtInKotlin=false` 会关闭 AGP 9 现在内置的 Kotlin 支持，而 `android.sdk.defaultTargetSdkToCompileSdkIfUnset=false` 会阻止 AGP 推断 `targetSdkVersion`）。请将它们移除：

```diff
# gradle.properties

- android.defaults.buildfeatures.resvalues=true
- android.sdk.defaultTargetSdkToCompileSdkIfUnset=false
- android.enableAppCompileTimeRClass=false
- android.usesSdkInManifest.disallowed=false
- android.uniquePackageNames=false
- android.dependency.useConstraints=true
- android.r8.strictFullModeForKeepRules=false
- android.r8.optimizedResourceShrinking=false
- android.builtInKotlin=false
- android.newDsl=false
```

### 将 core-ktx 迁移到 core

`androidx.core:core` 1.19.0 将之前由 `core-ktx` 提供的所有扩展函数合并到了 `core` 中，因此 `core-ktx` 变成了空的兼容性制品。移除单独的 `androidxCoreKTXVersion` 变量（改为复用 `androidxCoreVersion`），并依赖 `core` 而不是 `core-ktx`：

```diff
dependencies {
-   implementation "androidx.core:core-ktx:$androidxCoreVersion"
+   implementation "androidx.core:core:$androidxCoreVersion"
}
```

### 移除 targetSdkVersion，更新 minSdk / compileSdk

如果未设置 `targetSdkVersion`，AGP 9 会根据 `compileSdkVersion` 推断其值；而在库模块（你的插件的 `android/build.gradle` 就是库模块）中，`targetSdkVersion` 在运行时不会产生任何影响，因此请将其完全移除：

```diff
# build.gradle

android {
-    compileSdk project.hasProperty('compileSdkVersion') ? rootProject.ext.compileSdkVersion : 36
+    compileSdk = project.hasProperty('compileSdkVersion') ? rootProject.ext.compileSdkVersion : 37
    defaultConfig {
-        minSdkVersion project.hasProperty('minSdkVersion') ? rootProject.ext.minSdkVersion : 24
+        minSdkVersion = project.hasProperty('minSdkVersion') ? rootProject.ext.minSdkVersion : 26
-        targetSdkVersion project.hasProperty('targetSdkVersion') ? rootProject.ext.targetSdkVersion : 36
    }
}
```

### 重命名默认 ProGuard 文件

AGP 9 已移除 `proguard-android.txt`——任何仍引用它的 `build.gradle` 都会在 Gradle 配置阶段失败，即使设置了 `minifyEnabled false` 也是如此。大多数官方插件已在 Capacitor 8 中切换到 `proguard-android-optimize.txt`；但如果你的插件（或其 fork）尚未切换：

```diff
buildTypes {
    release {
        minifyEnabled false
-       proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
+       proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
}
```

### 使用 R8 检查你的插件

Capacitor 9 应用默认会在 release 构建中运行 R8，因此，如果 R8 无法识别插件代码正在被使用，该代码就会在 release 构建中出问题。请检查插件是否存在以下情况：

- 通过名称查找的类或方法，或由原生代码（JNI）创建或调用的类或方法
- 未使用 `@SerializedName` 注解的 Gson 模型、低于 2.11 的 Gson，或被序列化为 JSON 的 `kotlin.Pair` 等库类
- 引用了插件未包含的类的依赖项；这会导致应用的 release 构建报出“Missing classes”。请将 R8 在应用的 `build/outputs/mapping/release/missing_rules.txt` 中列出的 `-dontwarn` 行添加进去。
- 低于 2.7 的 Room、低于 2.10 的 WorkManager，或低于 18.0.1 的 firebase-components；这些版本需要遵循[使用旧版 keep 规则的库](/main/android/troubleshooting.md#libraries-with-old-keep-rules)中的规则

将规则放入 `android/proguard-rules.pro`，并在发布插件时包含该文件。当此文件存在时，`@capacitor/plugin-migration-v8-to-v9` 会为你完成这项工作：

```diff
// android/build.gradle
defaultConfig {
+   consumerProguardFiles "proguard-rules.pro"
}
```

```diff
// package.json
"files": [
+   "android/proguard-rules.pro",
```

规则应尽量精简，因为它们会应用于所有使用你插件的应用；并且不要加入 `-dontobfuscate` 等全局选项，这些选项会导致应用在 AGP 9 下构建失败。要进行测试，请使用 `minifyEnabled true` 构建示例应用的 release 版本，调用每个插件方法，并检查其行为是否与 debug 构建一致。

### 移除独立的 Kotlin 插件

AGP 9 原生捆绑了 Kotlin Gradle Plugin（Kotlin `2.2.10`），不再需要单独应用该插件。如果你的插件仍然应用 `kotlin-android`（或 `org.jetbrains.kotlin.android`），并自行声明 `kotlin_version` / `kotlin-stdlib` / `kotlin-gradle-plugin`，请将它们移除，否则构建会因插件重复而失败：

```diff
buildscript {
-   ext.kotlin_version = project.hasProperty("kotlin_version") ? rootProject.ext.kotlin_version : '2.2.20'
    repositories {
        google()
        mavenCentral()
    }
    dependencies {
        classpath 'com.android.tools.build:gradle:9.2.1'
-       classpath "org.jetbrains.kotlin:kotlin-gradle-plugin:$kotlin_version"
    }
}
-apply plugin: 'kotlin-android'

dependencies {
-   implementation "org.jetbrains.kotlin:kotlin-stdlib:$kotlin_version"
}
```

### 为插件设置唯一的 Android namespace

AGP 9 默认将 `android.uniquePackageNames` 设为 `true`：如果插件的 Android `namespace` 与同一应用中的另一个库模块冲突，构建现在会失败，而不是像以前那样静默通过。最常见的原因是脚手架中遗留的默认值（`create-capacitor-plugin` 会在 `namespace` 提示中预填 `com.mycompany.plugins.example`，按 Enter 即会接受该值）。保留了原插件 `namespace` 不变的 fork 也可能导致同样的问题。请确保 `build.gradle` 中的 `namespace` 对你的插件而言是唯一的。

### 移除 jcenter()

Gradle 9 完全移除了 `jcenter()` 仓库辅助方法（自 2024 年起该仓库已重定向到 Maven Central）。任何仍调用它的 `build.gradle` 都会在 Gradle 配置阶段失败：

```diff
repositories {
    google()
-   jcenter()
+   mavenCentral()
}
```

### 将 iOS 部署目标提高到 16

如果你的插件会观察应用生命周期或 URL 打开通知，也请根据 Capacitor 8.5 中采用的 iOS UIScene 生命周期检查插件——请参阅[检查你的自定义代码和插件](/main/updating/8-5.md#audit-your-custom-code-and-plugins)。

更新插件的 `.podspec` 文件：

```diff
-  s.ios.deployment_target = '15.0'
+  s.ios.deployment_target = '16.0'
```

#### 兼容 SPM 的插件

更新 `Package.swift` 文件：

```diff
-    platforms: [.iOS(.v15)],
+    platforms: [.iOS(.v16)],
```

#### 使用旧版结构的插件

在 Xcode 项目中执行以下操作：在项目编辑器中选择 **Project**，然后打开 **Build Settings** 标签页。在 **Deployment** 部分，将 **iOS Deployment Target** 更改为 **iOS 16.0**。对所有应用 **Targets** 重复相同的步骤。

然后打开 `ios/Podfile`，将 iOS 版本更新为 16.0：

```diff
-platform :ios, '15.0'
+platform :ios, '16.0'
```

### 更新 Capacitor SPM 依赖

对于兼容 SPM 的插件，请更新 `Package.swift` 文件，使其指向当前的 Capacitor 9 预发布版本（Capacitor 9 尚未发布稳定版本，因此不能使用普通的 `9.0.0` 版本）。请使用最新的 alpha 版本，因为较早的版本存在与 Cordova 可选性相关的崩溃问题：

```diff
    dependencies: [
-        .package(url: "https://github.com/ionic-team/capacitor-swift-pm.git", from: "8.0.0")
+        .package(url: "https://github.com/ionic-team/capacitor-swift-pm.git", from: "9.0.0-alpha.6")
    ],
```
